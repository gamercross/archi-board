# 코드를 읽어 보드 채우기

보드는 **코드에 있는 것**만 그린다. 아직 없는 것은 상태 `todo`(없음) · `cand`(후보)로 두고 이름 끝에 `[제안]`을 붙인다.
추측으로 칸을 채우지 않는다 — 모르면 비운다.

## 순서 — 작은 것부터

1. **부품 목록** (객체 지도의 뼈대)
   - 진입점부터 찾는다: `package.json`의 `main` · `scripts`, `main.py`, `cmd/`, `server.*`, `index.html`, Dockerfile.
   - 따로 실행되거나, 따로 배포되거나, 다른 부품과 주소(API · 메시지)로만 말하는 덩어리 하나가 객체 하나다.
     파일 하나가 객체 하나일 필요는 없다. 보통 5~25개.
   - 묶음(packages)은 **돌아가는 곳**으로 나눈다: 사람 · 브라우저 · 서버 · 작업자 · 바깥 서비스.
2. **오가는 길** (순서도)
   - 사용자가 하는 큰 일 3~10개를 고른다(로그인, 저장, 결제 …). 하나마다 유즈케이스 하나.
   - 함수 호출을 따라가며 부품 사이를 넘는 곳만 칸으로 적는다. 칸마다 코드 표시(`POST /api/x`, `fn()`)를 붙인다.
   - 실패 갈래는 `alt`로 — 가장 흔한 것 한둘만.
3. **데이터** (데이터 지도)
   - 쓰는 곳을 grep으로 찾는다: `writeFile` · `localStorage` · `sessionStorage` · `INSERT|UPDATE` · ORM `save` · 캐시 `set` · 쿠키 · `.env`.
   - 놓이는 곳으로 묶는다: 메모리 · 브라우저 · 파일 · 데이터베이스 · 바깥 서비스 · 저장소(git).
   - 데이터마다 쓰는 곳(w) · 읽는 곳(r)을 **코드 위치로** 확인한다. 한도 · 사라지는 때 · 남기지 않는 것은 코드나 문서에 있을 때만.
4. **ArchiMate 창** (선택 — 크게 보기)
   - 동기(왜): README · 기획 문서에서. 없으면 창을 만들지 않는다.
   - 업무(프로세스 · 서비스): 사용자가 하는 일. 프로그램(구성요소 · 서비스 · 데이터 객체): 1~3에서. 기술(노드 · 기술 서비스): 런타임 · DB · 클라우드.
   - 이행(만드는 순서): 이슈 · 마일스톤 · 로드맵이 있을 때만.

## 객체 카드 한 장 채우기

| 칸 | 어디서 |
|---|---|
| `one` | 한 문장 — "무엇을 받아 무엇을 한다" |
| `how` | 진입 함수에서 위에서 아래로, 3~7줄 |
| `api` | 라우트 · 공개 함수 · 이벤트 이름 — `입구 — 설명` |
| `holds` | 그 부품이 가진 상태(변수 · 저장) |
| `fails` | `throw` · 에러 응답 · 재시도 · 시간 제한 |
| `rules` | 검증 · 권한 · 한도처럼 깨면 안 되는 것 |
| `change` | 같이 고쳐야 하는 파일 · 시험 |
| `files` | 그 부품의 파일 |

## 하지 않는 것

- 키 · 토큰 · 비밀번호 · 서버 주소(도메인 · IP · 포트)를 보드에 쓰지 않는다. 환경 변수 **이름**까지만.
- 사람 이름 · 연락처를 쓰지 않는다. 역할(`사용자`, `관리자`)로 쓴다.
- 엔진 파일(`board.js` · `board.css`)을 프로젝트에 복사해 고치지 않는다 — 고치면 자동 업데이트가 끊긴다.
