# 처음 보는 사람용 그림 — 보드의 앞면

보드는 두 사람이 본다. **처음 보는 사람**(사용자 · 평가자 · 새 팀원)과 **만드는 사람**(개발자)이다.
엔진 1.2부터 위 띠에 **처음 보는 사람 / 만드는 사람** 전환이 있고, 처음 보는 사람 쪽에는 `aud: 'view'` 창만 보인다.
보드를 새로 만들거나 크게 고칠 때는 **이 앞면부터** 만든다. 객체 지도 · 데이터 지도는 그 뒤다.

## 1. 먼저 — 처음 보는 사람이 묻는 네 가지

그림 하나가 질문 하나에 답한다. 답이 없는 질문이 있으면 그림이 모자란 것이다.

| 질문 | 답하는 그림 | 재료는 어디서 |
|---|---|---|
| 이게 뭐지? 누구를 돕지? | 한 장 그림 맨 위 두 띠(누가 쓰나 · 받는 도움) | README 첫 문단 · 기획 문서 · 화면 문구 |
| 어떤 차례로 쓰지? | 차례 사슬 — 시작 사건 → 단계 → 단계 | 화면 흐름 · 라우트 순서 · 온보딩 |
| 무엇이 그걸 받쳐 주지? | 한 장 그림 아래 띠(프로그램 · 남는 것 · 바탕 기술) | 부품 목록(reading-code.md 1번)을 묶어서 |
| 내 것은 어디로 가지? | (있으면) 데이터는 어디로 — 내 컴퓨터에 남는 것 / 밖으로 나가는 것 | 데이터 지도(reading-code.md 3번)를 줄여서 |

평가 · 발표용이면 둘을 더할 수 있다. **AI(또는 자동)는 어디서 하고 사람은 어디서 정하나**, **누가 무엇을 만들었나**. 이것도 같은 `view` 창이다.

## 2. 그림 둘이 기본이다

| 그림 | 모양 | 데이터 |
|---|---|---|
| **한 장으로 — 이렇게 돈다** (ArchiMate 층별 뷰) | 위에서 아래로 띠: 누가 쓰나 → 받는 도움 → 하는 일 → 프로그램이 하는 일 → 프로그램 → 남는 것 → 바탕 기술. 하는 일 띠에는 차례 틀 하나 | `layout: 'view'`. 상자의 종류로 띠가 저절로 정해진다(`row`로 바꿀 수 있다) |
| **차례 — 한 번 쓰는 길** (업무 과정) | 왼쪽에 시작 사건(갈매기 모양), 오른쪽에 큰 틀 하나, 틀 안에 단계가 왼쪽 → 오른쪽. 아래 띠에 그 단계를 돕는 프로그램의 일 | `layout: 'view'`, 틀 상자에 `kids: [단계 id …]` — 단계 사이 선은 저절로 그린다 |

- 한 장에 **상자 25개 안쪽**(30개가 넘으면 점검이 경고한다). 넘치면 그림을 둘로 나눈다.
- 차례 틀 안의 단계는 **3 ~ 6개**. 더 많으면 묶어서 이름을 붙이고, 자세한 차례는 다른 그림으로.
- 선은 그 그림이 말하는 것만. 모든 부품을 잇지 않는다. 쓰는 관계는 넷이면 충분하다:
  `serving`(돕는다 — 도움 → 사람, 프로그램 → 단계), `realization`(이룬다 — 단계 → 도움), `triggering`(이어진다 — 사건 → 틀),
  `access`(쓰고 읽는다 — 프로그램 → 남는 것). 사람이 틀을 맡으면 `assignment`.

## 3. 쉬운 말

| 하지 않는다 | 대신 |
|---|---|
| `POST /api/chat`, `server.js`, `useStore()` | "대화를 받는 서버", "화면" — 코드 위치는 `c`나 `see`로 만드는 사람 쪽에 |
| 요구 번호 · 이슈 번호 (`C-47`, `#251`, `F-103`) | 그 기능의 이름 |
| 내부 낱말 (`qwin`, `isl-col`, `docmap`) | 사람이 화면에서 보는 이름 |
| 긴 이름 | 이름은 **22자 안**, 덧붙일 말은 `sub` 한 줄, 자세한 말은 `d` |
| 영어 약어만 (RTM, MoSCoW) | 우리 말 이름 + 필요하면 `sub`에 약어 |

점검(`check.mjs`)이 이름에 주소 · 파일 · 번호 · 함수처럼 보이는 말이 있으면 경고한다.

## 4. 만드는 순서

1. **누가 보나** 한 줄로 정한다(예: "처음 쓰는 비전공자와 대회 평가자"). 창의 `desc`에 쓴다.
2. 1절 네 질문의 답을 README · 기획 문서 · 화면에서 찾는다. **코드에 없는 기능은 상태 `todo`나 `cand`로 두고 이름에 [제안]** — 지어내지 않는다.
3. 한 장 그림: 사람 → 도움 → 차례 틀 → 프로그램 → 남는 것 → 기술 순서로 상자를 놓고, 2절의 선만 잇는다.
4. 차례 그림: 시작 사건 하나, 틀 하나, 단계 3 ~ 6개, 아래 띠에 돕는 프로그램의 일.
5. 상자마다 `see`로 만드는 사람 쪽(객체 · 창 · 상자 id)을 잇는다 — 옆 칸에 "만드는 사람 쪽에서 자세히 보기"가 생긴다.
6. `start`를 한 장 그림으로, 따라가기(`tour`) 맨 앞에 보는 창만 비추는 차례 2 ~ 4개를 둔다(처음 보는 사람 쪽에서는 이 차례만 돈다).
7. `check.mjs`로 점검하고, 경고는 사용자에게 알린다.

## 5. 5초 시험 — 다 됐는지

처음 보는 사람 한 명에게 보드를 열어 주고 **5초 뒤 화면을 가린 다음** 묻는다.

- "이게 무엇이고, 누구를 돕나요?"
- "쓰는 사람은 어떤 차례로 쓰나요?"

둘 다 자기 말로 답하면 통과다. 막힌 곳은 그 질문에 답하는 그림이 없거나 말이 어려운 것이다 — 그 상자부터 고친다.
사람을 구할 수 없으면 사용자에게 이 시험을 부탁한다고 말한다(Claude가 대신 통과를 선언하지 않는다).
