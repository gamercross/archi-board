# archi-board

프로젝트 코드를 읽어 **무한 보드 한 장**으로 그려 주는 Claude Code 스킬이다.
구조를 설명하는 문서를 따로 쓰지 않아도, "이 프로젝트 아키텍처 보드 만들어줘" 한마디로 브라우저에서 끌고 확대하며 볼 수 있는 지도가 생긴다.

예시 보드: https://gamercross.github.io/archi-board/

## 무엇이 그려지나

| 보드의 구성 | 보여 주는 것 |
|---|---|
| **ArchiMate 창** | 동기 · 전략 · 업무 · 프로그램 · 기술 · 이행 층으로 나눈 상자와 선. 상자마다 상태(있음 · 일부 · 없음 · 후보 · 뺌)와 코드 위치 |
| **객체 지도** | 부품 하나를 카드 하나로. 맡은 일, 안에서 도는 순서, 받는 입구, 실패할 때, 꼭 지킬 약속, 고칠 때 볼 파일 |
| **데이터 지도** | 데이터가 놓이는 곳(브라우저 · 파일 · 데이터베이스 …)과, 데이터마다 쓰는 부품 · 읽는 부품 · 한도 · 사라지는 때 |
| **유즈케이스 순서도** | 사람과 부품 사이를 오가는 차례. 한 칸씩 따라가며, 객체 지도 위에서 같은 흐름을 점으로 볼 수 있다 |
| **판단 · 차트** | 사람이나 AI가 코드를 보고 매긴 값(열지도 · 막대 · 흐름도). 값마다 근거와 기준을 함께 둔다 |
| **카드 창 · 화면 사진** | 장면 · 단계 카드, 화면 사진, 앱 × 유즈케이스 표 |
| **따라가기** | 큰 그림에서 세부로 안내하는 "흐름 따라가기" 차례 |

처음에는 객체 지도 + 데이터 지도 + 유즈케이스 2~3개로 시작하고, 필요하면 ArchiMate 창과 차트를 더한다.

## 어떻게 동작하나

보드는 **파일 두 개**다.

```
docs/board/
├── index.html       틀 (고치지 않는다)
└── board-data.js    내용 — 스킬이 쓰고 고치는 파일은 이것 하나
```

1. **코드를 읽는다.** 부품 → 오가는 길 → 데이터 → (있으면) 목적 · 계획 순서로, 코드에서 확인되는 것만 모은다. 모르는 칸은 비워 두고 지어내지 않는다.
2. **`board-data.js`를 쓴다.** 형식은 [`data-format.md`](skills/archi-board/references/data-format.md), 읽는 법은 [`reading-code.md`](skills/archi-board/references/reading-code.md).
3. **점검한다.** `check.mjs`가 없는 id · 잘못된 종류 · 숫자 범위 · 근거 빠짐을 브라우저 없이 찾는다.
4. **엔진이 그린다.** `index.html`이 공용 주소의 엔진(`engine/v1/`)을 불러와 데이터를 그린다. 엔진이 좋아지면 데이터를 다시 만들지 않아도 보드가 바뀐다.

코드가 바뀌면 "보드 업데이트해줘"라고 한다. 바뀐 부품 · 데이터 · 순서만 다시 읽어 그 칸만 고친다. 상태를 바꿀 때는 근거(파일 · 커밋)를 대화에서 말해 준다.

### 판단 · 차트

코드가 숫자를 주지 않는 값(위험도 · 복잡도 · 진척 · 흐름의 양)은 사람이나 AI가 판단해 `insights`에 적는다.
엔진이 열지도 · 막대 · 흐름도로 그리고, 창 · 상자 · 객체 · 데이터 패널에서도 연결해 보여 준다.
같은 코드를 보고 점수가 달라지지 않도록 **값의 기준(`rubric`)을 먼저 쓰고, 값마다 근거(`basis`)를 단다.** 근거가 없으면 점검이 경고하고, 패널에도 "근거 없음"이 뜬다.

### 이렇게 말하면 쓰인다

- "아키텍처 보드 만들어줘" · "구조를 한 장으로 그려줘"
- "객체 지도 · 데이터 지도 그려줘" · "ArchiMate로 그려줘"
- "보드 업데이트해줘" · "board-data.js 고쳐줘"
- "부품별 위험도를 열지도로 보여줘"

### 지키는 것

- 키 · 토큰 · 비밀번호 · 서버 주소 · 사람 이름은 보드에 쓰지 않는다. 환경 변수는 **이름**까지만.
- 엔진 파일을 프로젝트에 복사해 고치지 않는다. 엔진에 없는 기능이 필요하면 이 저장소에 이슈로 남긴다.

## 설치 — Claude Code에서 두 줄

```
/plugin marketplace add gamercross/archi-board
/plugin install archi-board@archi-board
```

그다음 프로젝트 폴더에서 "이 프로젝트 아키텍처 보드 만들어줘"라고 말하면 된다. 결과는 `docs/board/`에 생긴다.
`docs/board/index.html`을 브라우저로 열면 된다(엔진을 받으려면 인터넷이 필요하다). 점검 스크립트는 Node 18 이상이 있어야 돈다.

## 업데이트가 저절로 되는 두 곳

| 무엇 | 어떻게 |
|---|---|
| **이미 만든 보드** | 보드는 엔진을 `https://gamercross.github.io/archi-board/engine/v1/`에서 불러온다. 엔진이 좋아지면 다시 만들지 않아도 보드가 바뀐다. |
| **스킬** | `/plugin` → Marketplaces → `archi-board` → **Enable auto-update**를 한 번 켠다. 다른 사람의 마켓플레이스는 기본이 꺼짐이다. 손으로 받으려면 `/plugin marketplace update archi-board` 다음 `/reload-plugins`를 한다. |

`version`을 일부러 비워 두었다. 그래서 이 저장소에 푸시할 때마다 새 버전으로 친다.

## 인터넷 없이 · claude.ai 아티팩트로

`board.single.html`은 엔진을 안에 넣은 한 파일 사본이다. 인터넷 없이 열거나 claude.ai 아티팩트로 올릴 때 쓴다.
엔진이 안에 들어 있으므로 **저절로 바뀌지 않는다.** 스킬에게 "보드 다시 묶어줘"라고 하면 새 엔진으로 다시 묶는다.
묶은 파일만 남아 있으면 `unpack.mjs`가 데이터를 꺼내 주므로, 고친 뒤 다시 묶을 수 있다.

## 구조

```
engine/v1/board.js · board.css      그리는 엔진 (GitHub Pages로 나간다)
skills/archi-board/SKILL.md         Claude가 따르는 절차
skills/archi-board/references/      데이터 형식 · 코드 읽는 법
skills/archi-board/assets/          보드 틀 (index.html)
skills/archi-board/scripts/         check.mjs (점검) · inline.mjs (한 파일로 묶기) · unpack.mjs (묶은 파일에서 데이터 꺼내기)
examples/memo/                      예시 보드 (작은 메모 앱)
```

## 엔진을 고칠 때 (관리자)

- **v1 안에서는 칸을 더하기만 한다.** 이미 있는 칸의 뜻을 바꾸거나 칸을 지우면 모든 사람의 보드가 깨진다.
- 형식을 깨는 바꿈이 필요하면 `engine/v2/`를 새로 만들고 데이터는 `format: 2`로 한다. 그동안 `v1`은 그대로 둔다.
- 푸시 전에 확인할 것:
  - `node --check engine/v1/board.js`
  - `node skills/archi-board/scripts/check.mjs examples/memo/board-data.js`
  - 차트를 고쳤다면 예시 보드의 `판단 · 차트` 단추로 세 가지가 다 그려지는지 본다
  - 예시 보드를 브라우저로 한 번 연다
  - CI(`.github/workflows/check.yml`)도 같은 것을 돈다.
